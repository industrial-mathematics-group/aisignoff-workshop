Change something, in the browser

  1. Edit: open the file → pencil. New: Add file → Create new file. Upload: Add file → Upload files.
  2. Commit changes… → Create a new branch for this commit and start a pull request → Propose changes.
  3. Create pull request.
  4. The checks turn red: tick the AI declaration in the description (you can tick right there).
  5. Checks green → Merge pull request → Confirm merge → Delete branch.

Red check?

Click Details on the check. Usually: no or two G boxes · G1–G3 without a model · only H0 where H1 is required · A1–A3 without findings line · A2/A3 without report · a file in reviews/ changed, or a record file next to other changes · page not reloaded.

The AI declaration: G · H · A

0123
GHow much did AI generate?Nothing, I did it myselfAI helped: suggested, polished, structuredAI wrote big parts; I steered and editedAn AI agent did it mostly on its own
HHow did a human check it?Looked at the whole: does what was asked, plausibleTried it: reran or recomputed key results, read the important partsEvery line: every sentence, number, formula, referenceIndependently confirmed: another method, or a second person
ADid an independent AI check it?No (the chat that wrote it checking itself doesn't count)A fresh AI session checked it, without the original chatA different, capable model checked it; report committedDifferent model with new evidence (tests, recomputation) + report
  • G: tick exactly one, the highest of any substantial part. G1–G3: tick the model(s) too.
  • H, A: tick the highest level you actually did (H2 includes H0, H1). Nothing under A = A0.
  • You are responsible for what you merge, whoever or whatever wrote it.
  • A1–A3: fill AI-Review-Findings: with the worst finding (none · trivial · minor · major · critical); A2/A3 also name model + report. Recorded, never blocking; major/critical: better fix and review again first.
  • Findings (F): F0 nothing open · F1 minor · F2 major · F3 critical · F- no independent AI review since the line last changed.
  • Minimums: a repository can require more ([policy] in its SIGNOFF.toml, e.g. at least H1).

IMGAgent: ask and sign off

In a new issue or a comment (not in a code box); folders separated by commas:
@IMGAgent ask notes, analysis
When does the coffee reach 60 °C?
@IMGAgent signoff
I checked results/summary.md line by line against the data. Please record H2, reviewer Jane Doe.
ask answers from those folders only. signoff confirms or asks → opens a pull request on SIGNOFF.toml → check Files changed, tick your human review, merge. One at a time. Without AI: New issue → Signoff: declare or attest files. @IMGAgent help
Set up a file: @IMGAgent setup aisignoff · reuse · docs · citation → a form with defaults → change what you need → tick Done → a pull request (G0).

Golden rules

One change per pull request · never put unpublished data, personal data or passwords into a public repository or an AI tool · when unsure, declare more AI generation and less review rather than the other way round, and say why in the description.

Releases and DOIs (Zenodo)

  1. Once: log in at zenodo.org with GitHub → GitHub → Sync now → switch the repository On; add a CITATION.cff (@IMGAgent setup citation).
  2. Each release: Releases → Draft a new release → new tag v1.0.0 → Publish release.
  3. Zenodo archives it and mints a DOI: version DOI (cite in papers) and concept DOI (always the newest; README badge).
  4. Practise on sandbox.zenodo.org: real DOIs can't be deleted.

Each file shows its own highest finding (F0–F3). reviews/ is add-only: a later review is a new file. The reviewer changes nothing; fixing is the author's.
